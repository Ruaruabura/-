# 个人 Agent Harness：第一阶段实现设计

日期：2026-10-21
状态：待用户审阅；尚未实施或验证订阅连接

## 来源与目标

需求原文保存在 [完整方案](2026-10-21-personal-agent-harness-proposal.md)，保持用户上传内容不变。本文件是 AI 对第一阶段的实现解释，不代表用户新增的原话或已确认的选择。

面向个人本地使用，交付可发送文字任务、查看执行进度、取消任务并回看全过程的网页工作台。Pi 是真实执行核心，原始记录独立于模型可用性。只允许经过验证的订阅连接；没有认证或额度不足时保存并暂停，不切换付费 API。

第一阶段成功标准：一条用户消息形成持久任务，经过受限 Pi 调用得到结果；用户能查看按顺序关联的原话、可见执行事件、助手输出和验证状态。没有可用账号时，记录、队列、取消和恢复仍可测试，但真实订阅验收保持未通过状态。

## 交付顺序与方案取舍

采用原方案的四阶段顺序：

1. 记录底座、任务状态、文字聊天、Pi 订阅验证。
2. 附件草稿、分块续传、本地预处理、语音和材料限制。
3. 来源笔记、修订、完整导出恢复和知识库。
4. Grok Bot 的受限 MCP 协作验证。

推荐先做第一阶段的完整纵向流程，原因是后续模块都依赖任务和事件的稳定标识。一次实现四阶段会把账号、媒体工具和远程连通问题混合，难以定位验收失败。仅制作静态界面不能验证记录可靠性或 Pi 接入，不作为交付路线。

本阶段不实现文件上传、语音转写、知识整理 Agent、外部助手委派或 MCP 服务；这些保持在总体交付范围内，后续各自设计和验收。

## 架构与边界

- 前端：React + TypeScript，中文聊天与工作记录两个视图。浏览器只访问本地后台，不持有模型凭证。
- 后台：Node.js + TypeScript，提供会话、消息、任务和事件接口；默认仅监听回环地址。限制请求大小、校验输入和来源，不开放任意跨域调用。
- 持久层：SQLite，启用外键与事务；文件放在可配置本地数据目录，忽略运行数据和凭证。
- 任务执行器：单个后台进程中的持久队列，一次最多执行一个 AI 任务。
- Pi 适配层：唯一允许与 Pi SDK 交互的模块；管理订阅认证状态、执行、流式事件和取消。SDK 具体版本及认证接口以实施时官方包与文档核验为准，禁止猜测接口或自行模拟订阅登录。
- 用量闸门：执行前检查认证验证状态、输入量、请求次数和时限。重试默认关闭；额度不足或验证状态未知时暂停。
- 记录器：先持久化事件，再通知界面。记录失败应停止进一步执行并明确报错，不能显示“记录完整”。

账号认证在运行工作台的用户电脑上通过受支持的 Pi 官方流程进行。凭证由对应认证机制管理，不存入消息、事件或版本库。云开发环境的 GitHub 身份不能视为用户的 ChatGPT 订阅身份。

## 数据与事件契约

稳定 ID 关联 conversation、message、task、event 和 result。

- message：会话、角色、原文、创建时间、关联任务；发送后的原文不可被后续纠正覆盖。
- task：来源消息、目标、状态、执行限制、暂停或失败原因、创建及更新时间。
- event：数据库生成的递增序号、事件类型、任务及消息引用、时间、经过字段白名单处理的载荷。
- result：文本成果、处理范围、完成或未完成事项、可用验证证据、外部会话 ID。

用户消息与任务创建在同一事务完成；状态变化与对应事件也在同一事务完成。发送接口接受客户端幂等 ID，网络重试不创建重复任务。

记录用户原文、助手可见输出、状态变化和可见操作。不得请求或保存隐藏推理，不把 AI 建议标为用户决定。只持久化明确允许的字段，错误消息不得包含凭证或认证响应原文。

## 任务状态和恢复

状态为 queued、running、paused、failed、completed、cancelled。

- queued 可进入 running 或 cancelled。
- running 可进入 paused、failed、completed 或 cancelled。
- paused 由用户明确恢复后进入 queued，或取消。
- failed、completed、cancelled 为本次执行的终态；再次执行创建关联的新任务。

启动时把遗留 running 任务置为 paused，记录 interrupted 原因，不自动重放可能产生副作用的操作。

取消 queued 任务立即生效；取消 running 任务先向适配器发送中断，适配器确认结束后才释放队列槽位。迟到输出不能把已取消任务改为完成。若中断失败，显示明确状态并阻止下一任务重叠执行。

## 首阶段执行边界

第一阶段先验证文字任务与受控工作目录中的只读工具。不默认暴露任意 shell 或写文件工具；扩展工具权限在后续专门验收。

默认输入上限为 20,000 字符，单任务最长 120 秒，单任务最多 3 次模型请求，无自动重试。以上是可配置工程默认值，不是订阅额度预测。适配器必须能够在每次模型请求之前执行闸门；若官方 SDK 无法支持，应停用相应多步能力并报告限制，不能仅靠提示词约束。

认证或订阅路径未验证时，任务以清晰原因暂停。验证状态记录验证时间和使用路径，不保存凭证，也不意味着永久有效。用量只展示服务实际返回的数据，未知剩余额度显示“未知”。验证真实费用还需用户核对账号的额外用量设置，系统不承诺仅凭缺少 API Key 即保证零额外费用。

## 接口与交互

提供创建和列出会话、读取消息、提交消息、读取任务、取消或恢复任务、按事件序号读取记录以及读取连接状态的接口。前端先使用带游标的轮询，减少流连接恢复的复杂度；接口保留以后接入 SSE 的空间。

聊天页显示消息、排队与执行状态、暂停原因、结果及取消操作。请求失败保留输入草稿；成功后清空输入。刷新后从数据库恢复历史。

工作记录页展示原话、助手可见输出、状态、错误和结果，按数据库事件序号排列。连接状态清楚区分未配置、待验证、可用和暂停；测试替身不能显示为真实 Pi 已连接。

## 验证方案

1. 持久层：事务回滚、事件排序、幂等发送、消息原文保留。
2. 执行器：串行执行、取消、迟到输出、超时、额度暂停、限制阻断、重启后暂停。
3. 适配器：用契约测试检查事件归一化和取消传播；替身仅用于自动化测试。
4. HTTP 集成：提交消息到结果与事件查询，验证无认证时仍保存消息并暂停。
5. 浏览器验收：发送、查看进度、取消、刷新恢复和工作记录；同时运行类型检查与生产构建。
6. 真实连接：用户官方登录后执行一个小型文字任务，核对认证路径、返回结果及可见用量。没有登录条件则明确报告此项未执行。

不以零测试、静态页面或模拟响应替代真实订阅验收。
